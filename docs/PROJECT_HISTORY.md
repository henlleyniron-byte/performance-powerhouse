# Project History and Maintainer Disclosure

Performance Powerhouse predates this GitHub repository.

The project was developed through multiple local-first web releases, deployment experiments and private handoff/QA packages before the source was migrated to GitHub in September 2026. Because those iterations did not originate in a Git repository, this repository does not manufacture retroactive commits or false contributor history.

## Maintainer

**Henlley Niron Pushparajah** is the project owner and primary maintainer.

Maintenance includes:

- defining the product's study-evidence model and scope;
- deciding which features are accepted or rejected;
- maintaining release packages and deployments;
- reviewing AI-assisted code changes;
- performing or commissioning QA checks;
- maintaining privacy boundaries and migration behaviour;
- updating documentation and resolving defects.

## AI-assisted development

AI systems have been used extensively as implementation and verification tools. This repository describes that openly rather than presenting AI-generated implementation work as unaided manual coding. The maintainer remains responsible for project direction, release decisions and the published software.

## Git history boundary

The first GitHub commit should be read as **"import existing maintained project into public open source"**, not as the project's original creation date.

## Relationship to the independently maintained ChatGPT Site

A related student-facing ChatGPT Site has historically been published at `https://al-performance-powerhouse.phenlleyniron.chatgpt.site/`. The public GitHub repository contains a maintained open-source snapshot, but **no automated upstream linkage between that site and this repository has been verified**. Therefore a GitHub commit or a green CI check does not prove the same change has reached the independently hosted site.

The maintainer reports further web-site iterations beyond the versioned GitHub source currently documented. Until the corresponding site version identifiers, source snapshots, release dates and asset hashes can be checked, these iterations must remain *reported but unverified as GitHub releases*. This distinction preserves historical work without inventing backdated commits or conflating separate deployments.

Any future release reconciliation should use verified source snapshots, actual build/deployment IDs, smoke-test results and a reversible plan before altering a live application with existing users.
