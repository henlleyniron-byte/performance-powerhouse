## Personal evidence and recovery

New isolated browser namespaces are `al_performance_powerhouse_chemistry_intelligence_v1` and `al_performance_powerhouse_biology_intelligence_v1`. Existing core, tracker, Physics, cloud and migration namespaces remain intact. The unit overlay reads existing Command attempts without modifying them. New practice records do not automatically create core attempts or cloud rows.

Practice stages record baseline, reattempt, fresh transfer and delayed retest. Clean evidence requires unaided work, no guesses, no exposed error, sufficient marks and performance within the learner's planned time. A 3-day retest must follow a clean novel transfer by at least 72 hours. A later failure reopens the cycle and requires fresh transfer again. These are local evidence heuristics, not external verification or mastery awards.

Share mode excludes private data at initial load, clears private rendered results when toggled, disables mutation paths and propagates through subject navigation. Imports validate all records before replacement. Unreadable stored bytes block ordinary writes and remain exportable for recovery. A denied write leaves current-session records exportable. Dedicated backups can be moved between the two sites manually. Study Tracker's complete backup also preserves raw Chemistry/Biology browser payloads; each subject's import accepts its matching payload from that bundle without modifying other subjects.

## Source limits and validation

The benchmark audits are source-attributed recovered evidence. This upgrade did not independently reread every original paper or marking scheme. Live external benchmark retrieval was unavailable. Counts, identifiers, allocations and label totals were reconciled against the recovered JSON; new all-year frequency or forecast claims are intentionally absent.

Validation includes production builds, TypeScript checks, existing regression suites, new source/denominator/filter tests, evidence and backup validation, DOM-harness initialization/submission/share/recovery checks, local link checks and duplicate-ID checks. Native browser QA was unavailable in this managed environment. DOM-harness checks do not establish visual layout or real-browser behavior. Both current production origins and audiences are retained.
