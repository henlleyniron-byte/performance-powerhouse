# Performance Powerhouse V21 — Reviewed Imports & Recovery

Bounded isolated candidate based on published V20 source `a089a3d141193fae8fbe0233d8df86571c33e239` (saved Site version45). This release fixes the existing direction-plan file-import lifecycle. It adds no learning feature, persistent store, data schema, namespace, runtime dependency or cross-site connection. The existing planning interface, academic records, Paper Observatory, worksheets and exact raw recovery exports remain available. Root owns final validation, source freeze and any supported publication.

## Confirmed defect and resulting behavior

The published UI checked privacy only after an asynchronous file read completed. A private → Share-safe → private round trip could therefore allow an earlier file read to reopen its private preview. Independent QA also reproduced older readA replacing an already displayed newer readB. These were synthetic imports, not an observation of real student records or demonstrated destruction of academic work. Failed baseline reports are retained outside the product candidate.

Each import now binds to its attempt, privacy epoch, exact visible fields and raw saved-plan/recovery coordination context. Another selection, file-picker or dialog cancellation, form editing, plan/draft actions, changed saved copies, Share-safe transition, page exit or host removal retires that review. A stale success, failure or cleanup callback cannot replace a newer preview, status or file selection. Returning to private view restores the current unsubmitted fields, but never revives the retired file or preview.

Apply binds to the particular displayed review object, selected merge mode and exact proposed result. It rechecks current fields and raw saved-copy context before invoking the existing guarded importer. Both fill-empty and deliberate replace modes remain. Invalid, unsupported or unreadable originals are not silently overwritten; existing raw exports retain their exact stored text. Separate form-draft debounce writes do not expire an otherwise unchanged review, while a newer plan/reviewed archive does. Existing checkpoint/conflict/rollback behavior and the five-copy reviewed-draft limit are unchanged.

Private current-field and raw/recovery exports check the current view and host. Direct `?share=1` views also block these actions. Saved downloads/printouts cannot be recalled; no guard claims to remove files already saved outside the page. Current-field export still exports the latest visible fields rather than claiming they were saved or completed work.

Late lifecycle QA also reproduced a detached draft timer reading removed field IDs and a global Ctrl+S callback looking up a removed Save control. Those synthetic failures are preserved as before evidence. Host removal now clears the queued draft timer, and both draft retention and keyboard Save refuse a detached host before reading fields or writing storage. A captured callback already queued before cancellation is also inert. The exact visible field values are left intact on the detached node; normal connected autosave and keyboard Save remain covered by positive controls. No production host removal or student-data incident was observed.

The final integration run also found an inherited verification-desk boundary: clicking Share-safe queued removal of private form DOM for 50 ms instead of removing it synchronously. A disposable browser confirmed that the form and exact draft remained in the DOM at click end; computed visibility was already hidden by existing CSS, so this did not establish visible-record exposure. The immediate removal assertion remains unchanged. Its failure left Share-safe enabled, which caused the three later missing-control integration failures; those are retained as consequences of the first failure rather than four independent defects.

Separate disposable-browser reproductions confirmed that detached verification Submit/Reopen callbacks could write while shared, and an old verification-file read could resume after a Share-safe/private round trip. The desk now refreshes synchronously on the Share-safe click while preserving the existing 50 ms delay for ordinary background clicks. Form reads, saves, source changes and exports require the current connected private view; form callbacks also bind to the exact rendered form and source. Reopen and import recheck that ownership after confirmation. File reads retire on another selection, cancel, form edits, rerender, privacy transition or page lifecycle change. Retired results and errors cannot replace the current notice, records or draft. Existing unsubmitted drafts remain in memory and restore privately. The verification ledger format, original bytes, isolated checkpoint writer and recovery validation remain unchanged.

## Evidence and limits

Mounted tests execute the actual independent PH UI/model/safe-store with synthetic browser storage. Cases cover normal native-shaped file review and both modes; unchanged legacy bytes and archived prior fields; privacy round trips; out-of-order success and failure; cancellation/Escape/file-picker cancel/cleared selection; latest edits during reads and previews; stale apply/mode callbacks; changed legacy/checkpoint/reviewed archive bytes; unchanged form-draft debounce; direct shared URL, page exit and detach/reattach; unreadable/future originals; malformed files; denied reads/quota and current/raw exports. No marks, completion or automatic study credit are created.

QA retains the original failing privacy fixture and independent A/B evidence. An early harness limitation (Linkedom's missing native select setter) was corrected with a positive normal-preview control before the baseline failure was accepted; that earlier fixture output remains evidence history, not a passing safety check. Focused tests are distinct from root's full application, lint/type/build, historical-data and real-browser release gates. Their exact counts and remaining skips belong to the final readiness report.

The verification regression uses actual bubbling clicks with a controlled timer queue, current and retired form handlers, delayed file reads, cancellation and page events. Positive controls retain native-shaped reviewed imports, private exports, exact legacy bytes and latest draft text without creating academic credit. The previous newer-legacy import test held a file input from before a rerender; its fixture now obtains the live input after opening/editing the chain, with every original recovery assertion retained. An initial new fixture attempt stalled while formatting a failed DOM-node-versus-null assertion; equivalent numeric count assertions preserve the immediate-removal condition and yield bounded failure reports. That attempt, the corrected baseline failures and the first post-fix 19-pass/1-fixture-failure run are preserved separately.

No real visitor profile, physical file-picker OS interaction, durable download storage, comprehensive assistive-technology audit, scientific correctness certification or official answer-key review is claimed. Browser origin storage remains subject to device/browser deletion and quota limits. Root's browser harness uses disposable synthetic profiles and same-origin fixtures; no private academic or cloud corpus is bundled.

Only current edition/PWA/metadata labels and the service-worker asset-cache revision advance to V21. Service-worker scope/start URL, project/access identity, package scripts/dependencies, lockfile and hosting are unchanged. Historical compatibility references retain their original version labels.
